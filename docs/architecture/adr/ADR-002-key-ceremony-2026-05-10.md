## Context

The aegis-policy repo bootstrap (Sprint 5/E1; PR #1; commit `9c25b38`) shipped `policy/verifier-policy-v1.yaml` with `required_keyids` set to `PLACEHOLDER_E1_5_CEREMONY_PENDING` — the trust-spine fingerprints were intentionally deferred to a later, separately-gated PR.

This ADR documents the **Sprint 5/E1.5 key ceremony** (Phase 1 executed 2026-05-10 per cosmic-flute §28.17) — the one-time event that produces the canonical Ed25519 + ML-DSA-65 public keys consumed by the verifier kit + reusable workflow + all downstream consumers pinning aegis-policy by SHA.

The decision to land these specific bytes as a trust-spine commit is **load-bearing forever**: once committed to git history, the public-key bytes are publicly known indefinitely. A future rotation produces NEW keys but never removes the historical record. See ADR-001 §"Repo trust model" for the threat-model framing.

### Gate clearance

This ceremony required clearance of the AEGIS-self-tune-class gate per cosmic-flute §5 + §28.5. Three weighty dimensions were explicitly accepted (cosmic-flute §29.1):

1. **SOFTWARE-protection downgrade**: GCP KMS does NOT support HSM protection level for either `EC_SIGN_ED25519` or `PQ_SIGN_ML_DSA_65` as of 2026-05-10 (empirically verified during Phase 1 execution — `INVALID_ARGUMENT: Algorithm X is not supported for protection level: HSM`). The keys live at FIPS 140-2 Level 1 (GCP-managed SOFTWARE) not Level 3 (HSM). This is involuntary — HSM is unavailable, not chosen against.
2. **Trust-spine commit of forever-public bytes**: simpler than Sigstore TUF's 5-keyholder model, but consistent with single-engineer org reality + documented multi-keyholder growth path in ADR-001.
3. **NIST AU-10 bootstrap-event audit-trail gap**: cryptographic-signature attestation OF THE OVERRIDE DECISION ITSELF is structurally impossible at bootstrap (chicken-egg: the keys this ceremony establishes are needed to sign). Layered non-cryptographic controls (AEGIS Stage-2 decision row + PR review + commit signing + Slack post + cosmic-flute revision history) collectively meet AU-10's permits-multiple-mechanisms guidance. All subsequent self-tune-class decisions MUST be attestation-bound.

**AEGIS Stage-2 decision_id**: `9eae3455-3da1-4f2e-b74b-53b973300a60` (ESCALATE → OVERRIDE_APPLIED 2026-05-10 19:05 UTC; risk + profit gates correctly triggered with deliberate scoring; override authorized by sole risk_lead + security_lead per cosmic-flute §28.5.1).

## No offline ceremony

A traditional offline air-gapped ceremony was **NOT** performed. The keys were generated by GCP KMS via `gcloud kms keys create` — private bytes are never observed by any process outside the GCP KMS service boundary, even at SOFTWARE protection level. Per the cosmic-flute §28-prep research (preserved in §28.16), GCP's Access Transparency logs Google-employee actions affecting the key material; KMS audit logging captures every sign + get-public-key operation. These compensating controls substitute for the witness-attendance + tamper-evident-enclave properties of an offline HSM ceremony.

The decision NOT to perform an offline ceremony is consistent with:
- UC threat model (governance signatures for 20-repo portfolio under sole-engineer stewardship; NOT classified data, payment processing, or HIPAA-regulated workloads)
- HSM unavailability (would be the natural offline-ceremony venue, but GCP KMS does not support HSM for the chosen algorithms)
- Operational simplicity (rotation procedure documented in `docs/key-rotation-runbook.md` does not require human-attended witness events for v1)

| Control | Mechanism |

## Consequences

**Positive:**
- Sprint 6+ consumer repos can pin aegis-policy by SHA + verify their pinned trust artifacts against the live KMS keys (the offline-verifier path matches the issuer-side signing path byte-for-byte per ADR-012's uniform prefix-hash-and-sign)
- The fingerprint-parity gate (C5) catches any post-merge bytes ↔ fingerprints drift before it can propagate to consumers
- AU-N-B-1 production redeploy (cosmic-flute Phase 6) is unblocked once this PR merges

**Negative:**
- SOFTWARE-protection (FIPS 140-2 Level 1) is non-rotatable to HSM (Level 3) without a key migration — if a future hardening requirement mandates Level 3, would require a new keyring + new public bytes + new fingerprints + new aegis-policy v3.0.0 + coordinated cutover of all 20 consumer repos
- Single-keyholder model means key compromise of the sole engineer's GCP IAM principal is a single-point trust failure — partially mitigated by Access Transparency + audit logging + the rotation runbook's "if-compromise-suspected" emergency-rotation procedure

**Accepted (per §28.5.1 override affirmation):**
- The risk + profit AEGIS gate failures were deliberate signals (NOT pattern-matched defaults) and the override applied per the documented sole-risk_lead + sole-security_lead authority. Bootstrap exemption applies only to THIS one ceremony; all subsequent self-tune-class actions become attestation-bound.
